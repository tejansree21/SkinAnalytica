Limitations

Every open gap in SkinAnalytica, in one place, each with its current status and a pointer to the evidence. This page exists so a limitation can't be quietly left out of the story that gets told about this system — it's the same discipline behind docs/MODEL_CARD.md and docs/KNOWN_GAPS.md, written for a reader who isn't going to open either file.
Research prototype — not clinically validated No regulatory clearance in any jurisdiction. Nothing on this site or from this API is a diagnosis or a substitute for a dermatologist. See docs/REGULATORY_POSITIONING.md for what would need to change before that could be true.

External generalization

PartialDiscrimination transfers, the operating threshold doesn't

On the largest leakage-free external holdout available (n=143), AUC is 0.6131 (95% CI [0.5516, 0.6751]) — real, statistically significant discrimination. But the deployed threshold only delivers 42.7% sensitivity on this population, and no single threshold hits 80% sensitivity without specificity collapsing to 15.6%. This is a calibration-transfer problem, not a discrimination problem — diagnosed, not yet fixed.

Evidence: MODEL_CARD.md findings #5, #11, #12
MitigatedTwo separate root causes, two different fixes

Direct visual inspection of preprocessed images (not just more score-level statistics) found two opposite mechanisms behind external-population failures: SLICE-3D's source images are tiny (median 128px), a genuine resolution ceiling; MRA-MIDAS's are huge (median 3024×4032) with the lesion occupying a small fraction of the frame, so naive full-frame resizing wastes detail on background. A center-crop fix for the second mechanism is now shipped (see below) — the resolution-ceiling problem has no fix yet, since closing it needs retraining with resolution-robustness augmentation.

Evidence: MODEL_CARD.md finding #21
OpenMelanoma-specific discrimination on MRA-MIDAS is still weak

MelAUC (melanoma vs. everything else) on MRA-MIDAS is 0.54-0.58 — genuinely weak, unaffected by any fix shipped so far. The broader malignant-vs-benign question (can the model tell any cancerous lesion apart from benign ones) is a real, solid 0.70-0.74 — a metric-definition bug in an earlier read of this result made it look like near/below-chance collapse across the board, which it was not; see the preprocessing section below for the metric fix itself. The narrower melanoma-specific gap remains open.

Evidence: MODEL_CARD.md findings #20, #23
ClosedA classical lesion-detecting crop was tried and lost — dead end, not open

A more sophisticated classical-CV lesion detector (find the lesion, crop tightly to it) was built, unit-tested, and ablated against the simpler center-crop on both external populations. It lost on every metric that survived the metric-definition fix — it doesn't beat center-crop on MRA-MIDAS, and it measurably hurts MILK10k. Documented as a closed, honestly-reported negative result so it isn't re-attempted blind. A genuine improvement over center-crop would need a properly trained segmentation model, not a better classical heuristic — see "On hold" below.

Evidence: MODEL_CARD.md finding #22

Preprocessing change (2026-07-28)

ResolvedCenter-crop shipped; all 4 operating thresholds now re-derived or confirmed

Center-crop-to-square before resizing is now the default preprocessing in production (validated: a real gain on MRA-MIDAS, negligible cost on MILK10k). Because AUC is rank-order-only, the discrimination numbers reported throughout this page and the model card are trustworthy under this change, but fixed probability thresholds are not — so all four were re-derivation candidates. Age-band and skin-tone thresholds were cleanly re-derived on their original populations and updated. The TBP threshold was confirmed exactly unchanged (SLICE-3D crops are already square, so center-crop is a no-op there — a useful sanity check that the whole exercise was measuring the right thing).

Evidence: MODEL_CARD.md finding #25, docs/KNOWN_GAPS.md
Real change, not a bugMEL_THRESHOLD moved from 0.2385 to 0.5010 — production verdict routing changed

The original validation set behind 0.2385 was never a saved, reusable file — it was computed ad hoc in an earlier session and no longer exists on disk. A first substitution attempt produced a misleading ~2x jump that did not survive a same-population control check (scoring the substitute population under both old and new preprocessing showed the real center-crop effect is a small ~8% decrease, not a 2x increase) — so that number was correctly not shipped at the time. Rather than leave the threshold stuck against an unrecoverable population indefinitely, config/val.csv — a real, on-disk, genuinely-held-out validation split — is now formally adopted as the documented manifest going forward, and the threshold set to what it actually takes to hit 80% sensitivity on it under center-crop: 0.5010, with specificity improving 94.2% → 96.5% at that same sensitivity target. This changes production behavior for real requests, not just a model-card number — flagged prominently rather than left as a quiet config edit.

Evidence: MODEL_CARD.md finding #26, docs/KNOWN_GAPS.md

Skin-tone fairness

PartialNo confirmed disparity, but the extremes are unanswerable from available data

On MILK10k's dermoscopy holdout (overall MelAUC 0.8796, 95% CI [0.834, 0.921]), there's no statistically confirmed AUC disparity across the three adequately-sampled skin-tone bands. But the darkest (n=1) and lightest (n=51, only 2 melanoma) bands remain unanswerable from available data, and sensitivity at the deployed threshold spreads more (55.6%-76.9%) than AUC does — not yet confirmed as real vs. small-sample noise (13-28 melanoma cases per band).

Evidence: MODEL_CARD.md findings #9, #14

Out of scope

UnsupportedNon-dermoscopic (clinical/phone-camera) images

Zero validated performance on ordinary phone photos — MelAUC 0.63-0.78 there vs. 0.95+ on real dermoscopy. SkinAnalytica is dermatoscope-only. There is no reliable automatic detector for the wrong image type; /analyze's image_type_check field is a narrow, advisory aspect-ratio heuristic only (an earlier vignette-brightness signal was tested against real data, found unreliable, and dropped rather than shipped) — it flags genuinely extreme cases, never blocks inference, and should not be relied on as a real image-type classifier.

Evidence: MODEL_CARD.md finding #9, src/inference_utils.py's check_dermatoscope_likelihood()

Statistical rigor

OpenMetrics reflect a single train/val split, single seed

Confidence intervals throughout the model card come from bootstrap-resampling the existing scored predictions — that bounds sampling noise, not training-process variance. Real CIs on AUC/sensitivity would need k-fold or repeated-seed retraining of all three backbones, an order of magnitude more compute/time than anything done so far.

Open, now with confidence intervalsFlagged-precision collapses at realistic screening prevalence

Automation rate looks strong (77-97%) at every prevalence tested, but CANCER_FLAGGED precision drops to roughly 4-45% (95% CI) at realistic low-prevalence screening case mixes, vs. 82-91% on the enriched validation samples this project has mostly reported against. A proper bootstrap now backs both the external MILK10k numbers and, for the first time, the ISIC-2020 natural-prevalence figure (21.8%, 95% CI [16.4%, 28.1%]) — real statistical rigor, not a single-draw estimate anymore. What's still open: no genuinely natural-prevalence, zero-leakage, dermatoscope-domain holdout exists to remove ISIC-2020's separate leakage caveat (it was almost certainly in the training pool) — the confidence interval narrows sampling uncertainty, it doesn't resolve that leakage question.

Evidence: MODEL_CARD.md findings #16, #19, #27

Uncertainty quantification

DecidedShipped the ONNX-only disagreement signal, not PyTorch-based MC-dropout

MC-dropout works correctly offline against the real PyTorch checkpoints, but the deployed API only loads ONNX exports (dropout baked to identity at export time) and production never installs PyTorch. On the one real false-negative case tested, MC-dropout and the ONNX-only disagreement signal fail identically — both miss a case where all three backbones agree confidently and are wrong together — so the free, already-built option was chosen over committing real infrastructure cost for a method that isn't shown to do better on that case. SKINANALYTICA_ENABLE_UNCERTAINTY now defaults to true. It's explicitly kept false for the one live deployment (Render's free tier), though: loading the disagreement backbones adds ~2.1GB of fp32 model files on top of the primary model, which would almost certainly crash that service. Either way, this signal still won't catch confidently-wrong-in-unison errors — that blind spot isn't solved, just consciously accepted rather than left as an unmade decision.

Evidence: MODEL_CARD.md findings #7, #28, docs/KNOWN_GAPS.md

Data & licensing

Revisit before any commercial moveTwo training/validation sources are non-commercial-only

MILK10k is CC-BY-NC; MRA-MIDAS sits behind a non-commercial research data-use agreement. Training and evaluating on both was approved on the basis that this project is currently research/academic work. If SkinAnalytica ever moves toward commercial deployment, this decision must be revisited — any model trained on them would need to be retired or retrained without them.

Evidence: docs/KNOWN_GAPS.md, "Licensing decision (2026-07-22)"

Previously found, now closed

Included for completeness — these were real bugs found and fixed during development, not hidden after the fact.

  • Double-softmax bug: applying softmax a second time to an already-finished probability output silently distorted every threshold-based number while AUC looked fine. Fixed, regression-tested.
  • Temperature-scaling bug: skipping the calibration temperature broke bias-report sensitivity entirely (0.0%). Fixed.
  • Train/serve ensembling-formula mismatch: the training notebook and the deployed ONNX graph used two different pooling formulas. Practical impact fixed (threshold corrected to 0.2385); the notebook itself still has both formulas, tracked in RETRAIN_PLAN.md for the next retrain.
  • Unauthenticated patient-data endpoints: all six patient-data endpoints now require an API key, fail closed if unset.
  • Malignant-vs-benign AUC metric bug: ranking by melanoma-score alone under-credited true BCC/AKIEC cases in a broader malignant-vs-benign comparison, making MRA-MIDAS look far worse than it was. Fixed at the source, every affected result re-run and corrected in place.
Full evidence, confidence intervals, and the complete chronological record live in docs/MODEL_CARD.md and docs/KNOWN_GAPS.md — this page summarizes both, it doesn't replace either.
