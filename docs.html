Documentation

A 3-model ensemble (EfficientNetV2-S + ViT-L/16 + ConvNeXt-Large) for 7-class dermoscopy lesion classification, served over a plain JSON/multipart HTTP API.

Base URL

http://localhost:8001

Auto-detected per environment — see env_config.js. Local dev defaults to port 8001.

Core endpoint

POST/analyze
requires X-API-Key
Single image → classification, verdict, and full probability breakdown.
ParamTypeNotes
filemultipartRequired. JPEG/PNG/TIFF/BMP, max 20MB.
patient_idstringOptional. Used for later /patient/{id}/history lookups.
patient_ageintOptional. Selects an age-conditional melanoma threshold.
patient_sexstringOptional. Stored, not currently used in threshold selection.
capture_modestringOptional. "tbp" for 3D-total-body-photography-style crops — uses a separately-calibrated threshold. Omit for standard dermatoscope images.
skin_tone_classint (0–5)Optional, provisional. Only 2/3/4 have a calibrated threshold — see Known limitations.
curl -X POST "$BASE/analyze" \
  -H "X-API-Key: your-key-here" \
  -F "file=@lesion.jpg" \
  -F "patient_age=54"

Response includes image_type_check — a narrow, advisory heuristic (aspect ratio only, no vignette check — see Known limitations for why) that flags genuinely extreme image shapes. Never blocks inference; the UI shows a warning banner when it triggers.

requires X-API-Key
Same result, formatted as a FHIR R4 DiagnosticReport resource.
GET/patient/{patient_id}/history
requires X-API-Key
All scans on record for a given patient ID, most recent first.
GET/audit/log
requires X-API-Key
Recent scan verdicts, no patient identifiers. ?limit=50.

Authentication

Every endpoint that touches patient data — /analyze, /analyze/batch, /report/*, /patient/*/history, and /audit/log — requires an X-API-Key header, matched against SKINANALYTICA_API_KEY on the server. If that variable isn't set, the server fails closed (503) rather than silently running unauthenticated.

On this site, click 🔑 Add API key in the top-right of any page — the key is typed in by you and held only in this browser's localStorage, the same model as Swagger's own "Authorize" button. It is never embedded in this page's source, never sent anywhere except as that one header, and never leaves your browser.

curl "$BASE/patient/demo123/history" \
  -H "X-API-Key: your-key-here"

Known limitations

The short version: real, measured external-validation gaps, an unresolved fairness question, no support for non-dermoscopic images, and no clinical validation. A dedicated Limitations page lists every open gap with its current status and evidence — this section used to duplicate that list inline; now it just points there so the two can't drift apart.

Full findings, evidence, and confidence intervals live in the project's docs/MODEL_CARD.md — limitations.html summarizes it for a non-engineering reader, neither replaces that record. For what these limitations mean for any future clinical/regulatory claim, see docs/REGULATORY_POSITIONING.md.
